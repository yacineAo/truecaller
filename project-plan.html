Project plan · Android app

SAASCOM Caller: know who is calling before you answer

When a client calls someone in the sales or SAV team, their Android phone shows the client's file from the CRM (name, status, last call, payments, open requests) on top of the call screen. After the call, one tap saves a note back into the CRM.

01

How it works in 5 steps

Phone rings

A client calls an agent's phone, e.g. 0550 12 34 56.

App gets the number

Android gives the number to our app because it is set as the phone's "Caller ID" app.

Instant match

The app checks the client list saved on the phone (about 2,600 numbers). This takes milliseconds and works offline.

Ask the CRM

It calls the CRM API to get the full, up-to-date file: status, last call, payments, requests.

Show the card

A card appears over the call screen. When the call ends: "Log this call?" and the note goes to the CRM.

03

Which technology: React Native or Kotlin?

Android only → build it in Kotlin with Jetpack Compose. React Native's big advantage is one codebase for Android and iPhone. Without iPhone, that advantage disappears. The most important part (the code that runs while the phone rings) has to be written in Kotlin in any case. Doing the whole app in Kotlin means one language, one project and no bridge between JavaScript and native code.

Why Kotlin wins here

  • The ringing card, the screens and the API client share the same code and data models.
  • Direct access to Android call features (call screening, overlay, phone state) without a plugin layer.
  • Small, fast app that opens instantly, even when the phone was idle.
  • APK built on your PC with Gradle. No cloud build service needed.

React Native would still work, but…

  • Two languages: TypeScript for the screens + Kotlin for the ringing part.
  • The client card is built twice: native for the ring, React for the details screen.
  • Extra setup (Expo config plugin) to declare the call-screening service.
  • Its one plus here: quick UI fixes over the air (EAS Update) without reinstalling.

04

What we add to the CRM (soft_client_suivi)

Good news: the CRM already has most of the logic. Phone::normalize() and Phone::variants() handle Algerian formats (0550…, +213550…, 213550…). CallLog already updates last_contacted_at and auto-assigns the lead. Subscription, Payment and UserNote hold the money and SAV data. We only add a small, secure API.

  1. Install Laravel Sanctum for app login tokens: php artisan install:api. The CRM has no API login today.
  2. Add 8 mobile endpoints under /api/mobile, protected by auth:sanctum and rate limiting (table below).
  3. Search both phone columns. Lead::findByPhone() only checks whatsapp_phone today. Caller ID must also check secondary_phone: add an index on it and a Lead::findByAnyPhone() method. Also run a one-time command to normalize old secondary_phone values.
  4. One shared "log call" class. The «تسجيل مكالمة» form lives in LeadActions::callHistory(), but its save logic is inside the Filament action. Move it into App\Support\CallLogger so the CRM and the app use the same rules.
  5. Disabled users are locked out. When is_active becomes false, delete that user's tokens so the app stops working.
  6. Admin page «الأجهزة المرتبطة» in Filament: see each agent's connected phone and disconnect it.
MethodURLWhat it does
POST/api/mobile/loginEmail + password, returns a token. Active users only.
POST/api/mobile/logoutDeletes this phone's token.
GET/api/mobile/directoryLight list of all numbers: phone, name, company, stage (about 320 KB, about 50 KB compressed). Used for the instant match.
GET/api/mobile/lookup?phone=…The full card for one number.
POST/api/mobile/leads/{id}/callsLog the call: result, note, optional new status and reminder.
POST/api/mobile/leadsCreate a new lead from an unknown number. The normal "new lead" notification fires.
POST/api/mobile/leads/{id}/requestsOpen an SAV request (a UserNote with category «طلب عميل»).
GET/api/mobile/app-versionLatest APK version + download link, so the app can offer updates without the Play Store.

Fast and private: two-layer lookup

Layer 1 · on the phone

Local client list

Downloaded at login, refreshed every 2 hours and on pull-to-refresh. Holds only number, name, company and stage. Works without internet.

≈ 5 ms
→
Layer 2 · the CRM

Full live file

Last call, payments, requests, owner. Times out after 3 s. If there is no internet, the card keeps the Layer 1 info and shows "offline".

≈ 300–900 ms
Unknown numbers: a lead may have arrived from WhatsApp 5 minutes ago and not be in the local list yet. A setting decides whether to ask the CRM about numbers that aren't in the local list: on for company phones, off for personal phones, so private calls never leave the phone.
07

What happens inside the app while it rings

Android calls CallerScreeningService.onScreenCall() with the number. We answer "allow" right away: the app never blocks or delays a call.
PhoneNormalizer turns +213550123456 into 0550123456 (same rules as App\Support\Phone), then looks it up in the local list.
OverlayCard appears over the call screen with name, company and status.
Api.lookup() returns. The card fills in last call, money left and open requests.
CallEndWatcher sees the call end and shows a notification «سجّل المكالمة». Tapping it opens the after-call screen.

Android permissions (guided setup screen)

Needs Android 10 or newer. The first-launch screen asks for each permission in order and opens the right settings page directly.

Caller ID & spam appLets Android give us the incoming number. Only one app can hold this role: if an agent uses Truecaller, they must choose ours on the work phone.
Display over other appsDraws the card on top of the call screen.
Phone stateTells us when the call ends, to show "Log this call?".
ContactsAndroid skips caller-ID apps for numbers saved in contacts unless the app can read contacts. Agents often save clients, so we need it.
NotificationsBackup card if the overlay is blocked, plus the after-call reminder.
Battery: "No restrictions"On Xiaomi/Redmi, Oppo, Realme and Huawei, also turn on Autostart and Show pop-up windows while running in background. Otherwise these phones kill the app and no card shows.
09

Security and privacy

  • Login with the same CRM account. The token is encrypted with the Android Keystore.
  • HTTPS only, with rate limits on the API.
  • Disable a user in the CRM and the app stops working. Logout deletes the local list.
  • The card only shows what the agent can already see in the CRM.
  • No call recording, no SMS access, no upload of the phone's call history.
  • Client data on phones is personal data (Algerian Law 18-07), so the local list stays minimal.

Tech stack and folders

Android app (this folder: truecaller/)

  • Kotlin + Jetpack Compose (Material 3, RTL)
  • Min Android 10 (API 29)
  • Retrofit + OkHttp for /api/mobile/*
  • Room: the local client list
  • WorkManager: refresh the list every 2 hours
  • DataStore + Android Keystore: encrypted token
  • APK built with Gradle, hosted on the CRM server

CRM (soft_client_suivi/)

  • Laravel 12 + Sanctum (new)
  • Mobile API controllers and one JSON resource
  • CallLogger shared class
  • Filament page for connected devices
  • No new server needed: plain HTTPS requests work on the current hosting

Risks and how we handle them

RiskWhat we do
Some phone brands (Xiaomi, Oppo…) kill background appsGuided setup for Autostart and battery. Test on the team's real phones in Phase 1.
Only one Caller ID app per phoneOn work phones, our app takes the role instead of Truecaller.
Agents use personal phones"Ask CRM for unknown numbers" stays off, plus the work-SIM-only option.
No internet when the call arrivesLayer 1 still shows name and status.
Old numbers saved in odd formatsOne-time cleanup command using Phone::normalize().
Google Play rules on call permissionsIt's an internal app: install the APK from the CRM server (or a Play "internal testing" track). No public store listing.
Updating the app without the Play StoreThe app checks /api/mobile/app-version and offers the new APK.
